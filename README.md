# song-pipeline（歌曲流水线）

位置：`E:\_oc_work\`
一句话：**给一个歌名，它去 QQ 音乐搜、下载、转 mp3，可选一路跑到换音色的成品。**

---

## 完整链路

```
歌名  --fetch.ps1-->  QQ音乐搜索 --> 点下载 --> 文件落盘
                                                  |
                                     watch.ps1 监听两个下载目录
                                                  |
                            加密的 .mgg/.mflac --> 解密转 mp3
                            明文的 .ogg/.m4a  --> ffmpeg 转 mp3
                                                  |
                                          out\  成品（-Full 时再跑分离+RVC）
```

## 文件

| 文件 | 作用 |
|---|---|
| `fetch.ps1` | 环节⓪ 按歌名取歌：搜索 → OCR 确认 → 点下载 → 等落盘 |
| `watch.ps1` | 主程序 · 常驻看门狗，把整条链串起来 |
| `run.ps1` | 环节① 加密音频 → mp3（调 OpenConverter 的 CLI） |
| `uvr5_sep.py` | 环节② 人声 / 伴奏分离（UVR5 HP2 模型） |
| `cover.ps1` | 环节③ 分段跑 RVC 换音色，再和伴奏混音 |
| `fetch.log` / `watch.log` | 两段各自的日志 |
| `watch-state.json` | 处理台账（重启不重复跑） |

## 怎么用

```powershell
# 取一首歌（自动选搜索结果第 1 条）
powershell -File E:\_oc_work\fetch.ps1 -Title "打上花火"

# 指定第 N 条结果（同名多版本时用）
powershell -File E:\_oc_work\fetch.ps1 -Title "威风堂堂" -Row 2

# 取歌 + 一路跑到 RVC 成品
powershell -File E:\_oc_work\fetch.ps1 -Title "打上花火" -Full

# 只跑流水线（不取歌）
powershell -File E:\_oc_work\watch.ps1              # 常驻，只转 mp3
powershell -File E:\_oc_work\watch.ps1 -Full        # 常驻，跑完整套
powershell -File E:\_oc_work\watch.ps1 -ProcessExisting -Once   # 处理现有文件
```

## fetch.ps1 的关键实现细节（改之前先读这段）

QQ 音乐 PC 端是 **GF 自绘框架**（窗口类 `TXGuiFoundation`），UIA 树几乎是空的
——整个窗口只暴露一个节点。所以只能**截图 + OCR + 按坐标点**。

1. **搜索**：点搜索框（窗口比例 0.3197, 0.0513）→ 剪贴板 + Ctrl+V → Enter。
   中文只能走剪贴板，`SendKeys` 发不了。
2. **确认搜到**：截图跑 Windows 自带 OCR（zh-Hans-CN），拿第一行文本跟歌名做
   字符命中率比对，`>= 0.5` 才算命中，否则抛错并留下截图。
   OCR 对拉丁字母和汉字基本可用，**日文假名会错**（"梅とら"→"梅匕"），所以不能靠它认歌手。
3. **结果行**：第 1 行 y = 窗口高 × 0.3963，行高 × 0.0725，下载箭头 x = 宽 × 0.5424。
   **下载箭头只在鼠标悬停那一行时才出现**，所以必须先 Move 再 Click。
4. **下载面板**：弹出的是**独立的 320×326 小窗**，不是主窗口的一部分。
   - 不能靠 `MainWindowHandle` 找它 —— 弹窗出现时那个句柄会指向弹窗本身。
   - 要用 `EnumWindows` 枚举进程内所有可见的 `TXGuiFoundation`，排除主窗口后取面积最大的。
   - 面板底部是**两个并排按钮**：左「会员下载」、右「歌曲下载券」。点左半边（0.219, 0.880）。
   - 品质默认就是**标准品质**，不用选。
5. **等落盘**：对比处理前后两个目录的文件快照，轮询 90 秒。

## 边界

- 只做界面点击，**不碰接口、不构造请求、不碰签名**。
- 没版权 / 要单独付费 / 会员等级不够的曲子，点了也不落盘，脚本会如实报
  "点了但没落盘"并留截图，不会假装成功。
- `-Row` 只能选"第几条"，**判断不了哪个版本是你想要的那版**。
  同名一片的情况下（比如"威风堂堂"有 400+ 条翻唱），先跑一次不加 `-Full`，
  看落盘文件名对不对，不对再用 `-Row` 换。

## 踩过的坑（别重复踩）

1. **PowerShell 5.1 读无 BOM 的 UTF-8 .ps1 会按 GBK 解析。**
   函数里的中文注释会被解析成乱码，进而把后面几行吞掉 —— 表现是"函数莫名其妙返回空"。
   这个目录下所有含中文的 `.ps1` **必须存成 UTF-8 with BOM**。
   改完用 `Set-Content -Encoding UTF8` 重写一遍即可。
2. **找主窗口必须按标题，不能按"面积最大"。**
   弹窗出现时 `MainWindowHandle` 会指向那个小面板；主窗口最小化时面积只剩 160×28，
   会被 490×381 的对话框比下去 —— 于是脚本抓着对话框去点，全程都在对错的目标操作。
   正确做法：`EnumWindows` 枚举后按 `title=[QQ音乐]` 认。
3. **按名字杀进程会杀掉自己。** `CommandLine -like '*watch.ps1*'` 会命中正在执行这条命令的
   PowerShell 自己。要加 `-ne $PID`。
4. **右键列表行不会弹菜单。** 下载按钮是 hover 出来的行内图标。
5. **后台进程抢不到前台焦点。** 直接 `SetForegroundWindow` 会被 Windows 前台锁拒绝。
   要先 `keybd_event(ALT)` 敲一下解锁，不行再 `AttachThreadInput` 挂到前台线程上。
6. **找下载面板必须只认可见窗口。** 进程里有一堆隐藏的辅助窗口（480×605 那种），
   不过滤可见性的话"面积最大"会挑中它们，于是点到一个不存在的面板上。
7. **hover 会压暗第一行的白字。** 截图前必须把鼠标挪到空白处（窗口右下角），
   否则第一行的歌名扫不到（b 值从 255 掉到 240 以下），行号整体错一位。

## fetch.ps1 怎么定位到某一首歌（核心）

**不要猜坐标。** 早期版本用固定行高、固定 y，全错：

- 行高不固定：带"精品单曲"标签的行 56px，不带的 34px
- 第一行的位置也随内容变（实测 328 / 366 都出现过）

**正确做法是找歌名文字本身。**

列表里三种颜色分工明确：

| 内容 | 亮度 |
|---|---|
| **歌名**（纯白粗体） | b > 240 |
| 歌手 / 专辑 / 时长（灰字） | b ≈ 150~180 |
| 列表背景（纯色） | b ≈ 117 |

所以只统计"纯白像素"，就能把歌名行从整行内容里剥离出来：

```
for y in 300..690:
    cnt = 数 x=316..560 里 b>240 的像素
    连续 cnt>=3 的 y 段 → 一首歌名，取段中心
```

实测（"夜に駆ける"搜索页）：`366, 424, 482, 540, 598, 656` —— 高度全 13px，间距全 58px。

**歌名的 y 就是下载箭头的 y。** 窗口由 `Fix-Window` 每次强制钉成 `(0,0) 1226×800`，
所以这套坐标是绝对的。

## 2026-10-28 凌晨：取歌环节打通后的实测与修正

### 定位行的方法换了两次

| 版本 | 判据 | 结果 |
|---|---|---|
| v1 | 固定行高推算 | 错。行高在 34~56px 之间浮动 |
| v2 | 歌名文字是纯白（b>240） | 部分错。文字被叠加层压暗时整行漏掉，导致把第 4 首当第 1 首 |
| **v3** | **每行左侧的封面缩略图**（x=262~305，约 40px 彩色块） | **对。每行都有、行间没有、不受文字明暗影响** |

v3 实测（"千本桜"搜索页）：`y = [376, 434, 492, 550, 608, 666]`，
第 1 首 376，和人工标注的红框中心一致。高度 <25 的段要丢掉（那是表头"歌名/歌手"）。

### 已知问题

1. **个别 mgg 转不出完整音频。** Pretender 和 残酷な天使のテーゼ 两首，
   `.mgg` 完整落盘（2.86 / 3.55 MB），但 OpenConverter 只解出 2.5 秒就返回退出码 0。
   手动重转结果一样，不是时序/并发问题。**原因未查明**，怀疑是 mgg 变体不受支持。
2. **`selftest.ps1` 的判定只看下载。** 它现在仍会报"5/5 成功"，
   因为没校验成品。要看真实成功率必须另查 `ffprobe`。
3. **`-Full`（分离 + RVC）在 10-28 凌晨这一轮没有验证过。**

### 新增的成品校验

`watch.ps1` 原来只判断"mp3 文件存在"就报 ✓ —— 0.6 秒转完一首 4 分钟的歌也报成功。
现在加了 `Test-AudioOk`：**成品时长 < 30 秒一律判失败**，并输出
`FAILED: 产出的 mp3 时长不足（...），是残包`。残包不会留在 `out\`。

### 又一个路径坑（分离环节根本跑不起来）

`watch.ps1` 里 `$PySep` 原本指向 `D:\AI\Python310\python.exe` ——
**那个 Python 里没装 torch**。分离会直接：

```
ModuleNotFoundError: No module named 'torch'
分离耗时 0.1s
```

秒退，看起来像"分离失败"，其实是解释器选错了。

| Python | 版本 | torch |
|---|---|---|
| `D:\AI\Python310\python.exe` | 3.10.11 | ❌ 没有 |
| `D:\AI\RVC\.venv\Scripts\python.exe` | 3.12.10 | ✅ 2.7.1+cu118 |

**正确路径是后者。** `cover.ps1` 里的 `$py` 本来就是对的，只有 `watch.ps1` 写错了。

修好后实测（アイドル，4:36）：
